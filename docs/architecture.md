# Architecture

## Overview

```
Judge wallet (browser)
   │  1. register protection        2. sign protected swap
   ▼
apps/web ──── apps/api ──────────────────────────────────────────────────────┐
                │                                                            │
                │ 3. controlled-sandwich service (demo/)                     │
                │    front-run ─ victim ─ back-run  (Sepolia, one block)     │
                ▼                                                            │
         packages/detector ── identifies SANDWICH run around victim tx       │
                │                                                            │
                ▼                                                            │
         packages/simulator ── counterfactual replay vs observed output      │
                │                                     verifiedLossRaw        │
                ▼                                     │                      │
         packages/creditcoin                          │                      │
           ProofBuilder (USC SDK prover API)          │                      │
           BlockProver precompile verify              │                      │
           evidence normalization                     │                      │
                │                                     │                      │
                ▼                                     ▼                      │
         Creditcoin settlement ◄──────── authorizer EOA submits               │
           AncaSureClaims.submitVerifiedClaim(...)                            │
           payClaim() → ETH to judge                                          │
└────────────────────────────────────────────────────────────────────────────┘
```

## Trust boundaries

1. **Detection & simulation are deterministic** — pure functions over on-chain logs.
2. **Cross-chain truth comes only from Attestcoin**: the BlockProver precompile
   (`0x…0FD2`) verifies Merkle inclusion + block continuity proofs generated by
   the USC `ProofBuilder`. Static verification (`verifySingle`) is free; the
   Emit variants persist an on-chain audit trail on Creditcoin.
3. **Contract-side trust is minimized**: `AncaSureClaims` accepts verified losses
   solely from the `authorizer` address (the backend signer whose submission is
   itself derived from pipeline outputs — see `claim-rules.md`).
4. **Nothing depends on attacker cooperation.** All inputs are public chain data.

## Module notes

* `packages/detector` and `packages/simulator` are **verbatim ports** of the
  validated MEVdetector logic (`detectSandwichRun`, `simulateSandwich`,
  `reserve-reconstruction`). Do not refactor their internals without a green
  regression suite including the golden fixture.
* `packages/shared/src/config.ts` centralizes the 70% ratio, policy caps, and
  source-chain registry so the contract ABI numbers and TS side stay in sync.
* Chain keys are resolved at runtime from the CC3 ChainInfo precompile (never
  hard-coded guesses), overridable via `CC_CHAIN_KEY_*`.
